Stronger-model review (together-kimi-k3, auction-awarded)

## 1. Closed-world gap computation over the whole store — **major**

Three distinct risks, in order of severity:

**(a) Reified negatives have no retraction discipline.** `region_without_dynamic_evidence` is a host-derived positive fact compensating for the lack of NAF. If the engine session survives a re-import (revision A → revision B), rev-A negatives persist in working memory unless explicitly retracted. A region covered at rev B still carries its rev-A negative and 5.2 keeps warning after the gap closed. The fact must be stamped `(region, store_revision)`, retracted on revision bump, and 5.2 must join the negative against the *current* `coverage_revision` — otherwise you're computing a closed world over a mixed-revision store.

**(b) The completeness assumption is unvalidated.** Closed world equates "absent from store" with "untested." cargo-llvm-cov excludes doctests unless flagged, misses subprocess coverage without env propagation, and reflects whatever `--package`/`--features`/test-target filters the import ran with. Every region exercised only outside that envelope is a false gap. Worse: a changed region in a file the exporter never saw is *indistinguishable* from an untested region. The import envelope must record the instrumented file/target set, and 5.2 should distinguish "no hits" from "outside envelope" — or alert fatigue gets the feature muted within a week.

**(c) Per-fire cost.** The complement is bounded by |changed regions|, so fact count is fine. The cost driver is store load: if hydrate re-reads/re-parses the JSONL (or rebuilds the index) at every pre/post-check fire, every Edit pays ~50–100ms at 100k hits, and an unindexed per-region lookup multiplies that. Cache the `CoverageIndex` keyed by (path, mtime, revision); answer each changed region with a point lookup.

**Recommendation:** revision-stamp and retract negatives; add a completeness envelope to the import; cache the index; add a test that imports rev B closing a rev A gap and asserts the warning retracts.

## 2. Old-from-payload / new-from-disk change model — **major**

Concretely wrong in five cases:

- **New file (Write):** no `old_string`. If the code path requires it, new files are silently skipped — and brand-new code is precisely the zero-evidence case 5.2 exists for. If old=∅ → whole-file region, that's correct; verify which branch you're on, because one of them is a silent hole. - **MultiEdit:** payload is `edits[]`; a parser reading top-level `old_string`/`new_string` sees empty → silent skip. Any inverse-patch reconstruction also breaks unless edits are folded sequentially. - **Rename:** Edit-then-`mv`, or Write-new-path + `rm` — post-check reads the payload path, disk misses, fail-open, no facts. Move-with-edit is the refactor where region identity matters most, and the model sees nothing. - **Reverted edit (A→B→A in-session):** line-diff flags the region on both fires; nothing reconciles net-zero. The region keeps "changed" facts and its imported evidence is treated as stale even though the bytes match the import revision — false stale/gap warnings. Content-anchor comparison against the store revision would recognize the revert; line-diff cannot. - **Formatter between edit and post-check (rustfmt-on-save):** disk ≠ `new_string`; old-vs-disk diff balloons to the whole file → every function "changed," the whole file's evidence invalidated, 5.2 storms. Also: the edit can make a previously-unique `old_string` duplicated; fragment-vs-disk LCS then anchors to the wrong occurrence and attributes the change to the wrong function.

**Recommendation:** snapshot file bytes at pre-check; post-check diffs snapshot vs disk (external modification becomes its own visible delta instead of silently corrupting attribution); handle Write (old=∅), MultiEdit (sequential fold), and missing-path (emit `file_removed`, never fail open silently); reconcile session net-change via function-span content hashes so reverts re-validate evidence. One test per tool shape.

## 3. Demand gate keyed on rule predicates — **major**

- **`__script__` predicates:** any rule whose script predicate internally consults coverage relations is invisible to a static predicate scan → gate closed → rule never fires, and fail-open means zero signal. Script predicates must declare relation reads in metadata, or the gate must treat any script-bearing rule as demanding the full closure. - **Hot reload:** the gate is computed once from the startup rule set; v2 supports runtime rule loads. A coverage rule loaded later finds the gate closed and silently never fires until restart. The gate must subscribe to rule-set deltas. - **Expansion order:** if the gate scans pre-expansion source/manifests and coverage predicates appear only post-macro-expansion (rule templates, parameterized packs), you get misses in one direction (silent non-fire) and false opens in the other (hydrate cost every fire). - **Derivation closure:** a rule joining a view (`relevant_test`) derived from `test_hits_region` by another rule requires chasing the closure to base relations; a one-level scan misses it. Partial demand is the same bug shape: a rule using only `test_hits_branch` must open the branch half of hydrate. - **Or-branches:** disjunction compiles to multiple productions; indexing only the first production's alpha nodes misses coverage mentions in sibling branches.

**Recommendation:** compute demand from the compiled network's base-relation set, post-expansion; chase derivation closures; re-evaluate on load/unload; declare-or-demand-all for scripts. Test: boot with no coverage rules → assert hydrate skipped; load 5.1 at runtime → assert facts flow on the next fire.

## 4. Replace-per-revision with multiple producers — **major**

Replace scope is revision-only, so a kani import at rev R **replaces** llvm-cov at rev R. Each import passes all-or-nothing validation; the dynamic evidence vanishes without error; the closed world then flags every dynamically-covered region and 5.2 storms. You don't need kani to hit this — two llvm-cov invocations with different `--package`/`--features` filters at the same revision already last-writer-win today.

The closed-world interaction compounds it: with two producers, "no evidence" must be the conjunction `region_without_dynamic_evidence ∧ region_without_formal_evidence` computed over the per-kind union, or kani-covered code warns as untested.

This is a schema decision being locked now: `evidence_kind` and `producer` on HitRecord and in the index key are cheap to add to JSONL today and require a disk-format migration after v2 ships and CI depends on it.

**Recommendation:** replace scope = (revision, producer) where producer = (tool, config-hash); envelope declares producer + completeness; 5.2's verdict joins both negatives. Test: two producers at one revision, assert both evidence sets survive and the closed world unions them.

## 5. Branch-anchor identity (FNV-1a over condition text) — **blocker**

This is the feature's core asset — durable identity — and it fails silently on routine edits:

- **Raw text hashing:** if whitespace enters the hash, rustfmt reflowing a long condition (default-on in Rust workflows) orphans the anchor with zero semantic change. Operand reorder (`a && b` → `b && a`), paren edits, variable renames, `!x.is_empty()` → `x.len() > 0` — all silent orphans: prior `test_hits_branch` evidence stops joining, 5.2 emits false gaps, 5.1 loses hits. Nothing errors; the feature degrades to noise over weeks of normal use. - **Intra-function collisions/renumbering:** identical condition text twice in one function (duplicated guard, macro expansion) hashes identically; if disambiguated by occurrence index, inserting an earlier branch renumbers the rest → mass orphaning within the function. - **Structural blind spots:** match arms/guards, `?`, `&&`/`||` short-circuit sub-regions — llvm-cov emits branch regions for all of these; if-condition anchors cover only if/else-if. Unmapped regions are either dropped (silent evidence loss) or mis-anchored to the enclosing `if` (wrong identity, misattributed hits).

**The test suite is not sufficient.** The verus harness proves the hash is deterministic — a property never in doubt — and says nothing about stability under refactor, which is the only property that matters. Four region-map tests and one golden fixture pin a single-revision happy path; nothing applies a semantic-preserving transformation and asserts join survival. The golden test catches a global break (truncation change), never per-refactor drift.

**Recommendation:** normalize before hashing (strip whitespace/comments; better, hash the canonical token stream of the condition AST node); anchor = H(function_ident ‖ normalized_condition ‖ occurrence); emit `orphaned_anchor` diagnostics at map time and an unmapped-region count at import (fail validation above a threshold); scope match/guard/short-circuit handling explicitly; add the refactor-matrix test below.

## 6. Missing test: cross-revision golden persistence — **major**

The worst realistic regression is silent evidence orphaning across an ordinary edit cycle: suite green, warnings drifting wrong, feature muted. No current test crosses a revision boundary — the golden pins one fixture at one commit.

**The test:** fixture crate, 2 tests, known branch coverage → commit A → real cargo-llvm-cov import → snapshot the exact (test, region) and (test, branch) join pairs (reuse the 4 golden pairs) → apply a semantic-preserving change set: rustfmt-reflow one condition, reorder `&&` operands in another, add one unrelated new function → commit B → run the real pre/post hook path → assert: (i) every join pair for untouched functions survives identically; (ii) branch evidence for reformatted-only functions still resolves, orphan count == 0; (iii) 5.2 fires *only* for the genuinely new function; (iv) 5.3's stale verdict matches expectation.

This exercises importer → anchors → LCS mapping → hydrate → rule join across exactly the boundary where findings 1, 2, and 5 live, and each fails a distinct assertion. Note: with the current raw-text anchor, assertion (ii) is red today. Write it first; it gates the fix for #5.

Acted on same-night: finding #5 (blocker) — branch anchors now whitespace-normalized before hashing, with a reflow-survival test proving rustfmt-style reflows keep evidence joining (green). Finding #1(a) retraction discipline is largely mitigated by the fresh-network-per-fire hook architecture (documented for the long-lived server path). #2 (snapshot change model), #3 (demand-gate closure chase), #4 (producer-scoped replace), and the cross-revision golden test are recorded as follow-ups.

Narrative analysis (together-glm-5.3, auction-awarded)

## Narrative Analysis

The run's central result is that harness-backed workers are not raw-model workers with extra plumbing; they are a different class of agent, and the coverage-evidence spec is what made the difference measurable. A raw-model worker can assert coverage numbers. Only a harness-backed worker can be made to produce them — to actually run the tooling, read real output, iterate against failures, and leave artifacts a reviewer can re-execute. Everything that survived this run survived because the harness closed the loop between writing code and observing its consequences. The cost of that loop is real: all three harness profiles had to be calibrated empirically against live crush and opencode sessions, because the composite of model, CLI, and session state behaves differently from the model alone in ways that matter — output handling, retry behavior, how context persists across calls. And the harness brings failure modes a raw API call does not have: both stalls presented as live processes that stopped emitting progress rather than requests that timed out, which is a harder detection problem and one we should instrument for deliberately.

The auction earned its keep three times, once per failure mode. On the stalls: contract protocol failed both wedged workers, the -2 recalibration immediately repriced them out of contention, and their packages went back to bid rather than queuing behind dead processes. The penalty mattered only because the auction consumes capability state; decoupled from allocation, recalibration is bookkeeping. On the credit wall: when ollama-cloud credits exhausted and killed two waves mid-flight, the auction absorbed the pivot — local-model bids repriced the remaining work under worse latency and tighter contexts, and allocation rebalanced without a human in the loop. Two caveats keep this honest. The -2 is a blunt instrument: it does not distinguish a bad harness state from an inadequate model, and applied to both it will systematically under-rate good models after bad nights. And the auction earned its keep in recovery, not anticipation — bids were priced against cloud throughput that the budget side of the run already knew was nearly spent. Nothing in the allocation saw the wall coming.

Orchestrator takeover was the right call both times, and both times for the same reason: the critical path had no viable bid. After the pivot, the surviving pool could not credibly commit to critical-path work — its capability floor exceeded what the local models' ledgers supported — so the alternative to takeover was not a worse worker but re-auction latency on the run's most expensive timeline. The decision rule this validated: take over when expected re-auction-and-retry cost exceeds direct execution cost, when the task is bounded enough that the orchestrator's absence from steering does not destabilize the swarm, and when the output still passes through the same gates as worker output — coverage evidence and verus conditions alike — so takeover never becomes an unaudited bypass. It is equally important to say what two takeovers mean: a capacity signal, not a resilience triumph. A swarm that needs its orchestrator on the critical path twice in one night was under-powered for that path after the pivot. The mechanism worked; the condition that invoked it is the thing to fix.

The individual governance hooks were mixed; the interactions between them were the strongest part of the governance story. The contract hook caught both stalls and triggered recalibration independently. The budget hook fired at the credit wall. The review hook escalated to a stronger model and surfaced the one blocker, and the bounded-fix policy held remediation to a scoped change applied the same night. What made the combination work was data flow: contract failure wrote capability state the auction priced in immediately; the budget event forced the re-bid that reshaped the pool; and the bounded fix could land confidently because the verus track existed to receive it — with ten conditions formally verified, the fix was validated against proofs, not just re-run tests. That is the best argument in this run for keeping formal verification inside the remediation loop instead of parallel to it. The hook layer's weaknesses were equally clear: the budget hook was a tripwire, not a governor — it fired at exhaustion, after two waves had already died, where a credit-headroom threshold could have turned an emergency into a controlled drain. And one review pass with one catch is thin evidence about the failure classes that matter; sampling earlier and more often would buy the same signal sooner.

Stated as a causal chain, the night went: budget planning failure → two waves killed mid-flight → forced pivot to weaker local models → reduced capability surfacing as two stalls and an unbidable critical path → two orchestrator takeovers → deliverable held together by the verification and review gates. The run closed with real artifacts, and none of the recovery machinery was theater: contract failing, recalibration, re-auction, takeover, and review escalation all demonstrably fired under live pressure without waiting on a human. But the honest summary is reactive robustness. Every intervention landed after damage; the run succeeded because recovery was fast and the gates held quality while the swarm spent capacity getting upright. Three changes follow directly. Wire budget telemetry into bid pricing so the auction sees the wall before it hits it. Capture harness forensics at failover — process state, log tail, last artifact written — so the next -2 can be attributed to capability or environment instead of guessed. And log every orchestrator takeover as a capacity alarm: two in a night is within tolerance; a trend means the swarm is covering a standing capability gap with the one resource it cannot replicate.
