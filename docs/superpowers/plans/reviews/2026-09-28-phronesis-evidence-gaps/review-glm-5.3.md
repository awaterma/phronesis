**Verdict: APPROVE WITH CHANGES** — the five-part decomposition and the semantic decisions (lexical-only ignore, common-dir worktree probing, redirect-aware adapter, encoding-bound harnesses) address the shortfalls at the root. ## Critical

**C1. Task C1 step 3 fails its own step-1 test, twice — and the failure mode is dangerous.** The token-split parser returns `Some("2")` for `>&2`: `"> &2"` — `strip_prefix("&>")` yields `"2"`, which doesn't start with `&`, so it becomes a file target. The attached-form loop never sees it as an fd-dup. The test asserts `None`. Quoted spaced targets break too: `&> 'out dir/all.log'` — `split_whitespace` yields `"&>"`, `"'out"`, `"dir/all.log'"`; the parser takes `"'out"` as the target. The test expects `"out dir/all.log"`. An executing agent that hits step 4 red may "fix" by weakening the assertions (e.g., dropping the `>&2` or quoted cases), inverting the security intent — a plausible wrong target like a file literally named `2` would then be read by `output_for`. **Fix:** replace the whitespace tokenizer with a quote-aware scanner (Task B1 already built the right shape: `first_word_or_quoted`); treat any token beginning `>&` or ending `&<digit>` as an fd-dup, and resolve the target through the same quoting rules as B1. Do not let the test move.

**C2. Task C2 step 1's "outside root" case cannot fail, and neither can the stated contingency.** `tempfile::tempdir()` lives under `std::env::temp_dir()`, which `output_for` explicitly allows, so the negative assertion fails for the reason being tested-as-allowed — and the fallback, `tempdir_in(root.parent().unwrap())` on a `/tmp/.tmpXYZ` root, resolves to `/tmp`, still inside the allowed root. The security pin in Review Focus 4 is therefore untestable as written. **Fix:** create the outside file under `env!("CARGO_MANIFEST_DIR")` (e.g., `tempfile::tempdir_in(std::path::Path::new(env!("CARGO_MANIFEST_DIR")))`): it is readable, outside the temp project root, and outside the OS temp dir. Also add the missing precedence pin: captured output non-empty wins over the redirect file (currently only the whitespace-only branch is tested).

## Major

**C3. Task A2 → A3 ordering turns the repo's own audit red mid-part, with hooks active.** After A2 lands, structural rules run on the still-listed `src/init.rs`, exposing nine `enforce-no-unwrap-in-src` violations; if any hook or CI runs `audit --fail-on block` between A2 and A3, the executor is blocked by the very rule the plan is hardening, and A3's commits may be rejected at hook time. **Fix:** reorder inside Part A: (1) add the `//! phronesis-allow:` markers and `doc_excepted` first (dormant while the entry exists), (2) delete the `src/init.rs` ignore line, (3) then A1/A2. Failing that, fold the ignore-line deletion into A2's commit.

**C4. Task A1/A2 make `.phronesisignore` unboundedly expensive for its most common legitimate use.** Bulk exclusions (vendored trees, `target/`, generated code) were previously skipped entirely; now every audit walks the tree twice and structurally scans every excluded file, so ignoring mass becomes *costlier* than scanning it. Nothing caps file count, size, or traversal. **Fix:** add a size cap on the excluded-set structural scan (reuse `MAX_FILE_BYTES_DEFAULT`) and state the cost trade-off in the A4 docs; consider keeping whole-dir semantics for a documented opt-out.

**C5. Task B1's "`git -C` wins" heuristic mis-attributes the head-mover.** `git -C /x diff && git commit -am x` commits in the shell's CWD (project root), but `command_repo_dir` finds the *first* `git -C` and returns `/x` — a missed commit, the exact shortfall. Worse: `cd wt && cargo test && git -C . commit` resolves `.` to the *project root*, while the commit lands in `wt`. The directory must be derived from the git invocation that actually moves HEAD. **Fix:** find the `git … commit…` token run first (the same predicate `command_may_move_head` presumably uses), then resolve that run's own `-C` if present, else the leading `cd`; add both compound cases to the B1 test. `cd /a\ b`, `sh -c "… commit …"`, and `(cd a && git commit)` silently fall back to the old blind spot — at minimum, log a "could not resolve repo dir" note.

**C6. Task C2 creates evidence from stale files.** A command that fails before truncating its redirect (`false && cargo test > run.log`, a typo'd package, a killed process) leaves yesterday's `test result: ok` in place; `command_exit` doesn't distinguish "output is old." The adapter then journals `outcome:test_pass` on 2025's log — false confidence, the exact failure class this part exists to kill. **Fix:** record the hook start time in `push` (it already exists) and require the file's mtime ≥ that time before reading; otherwise return `captured` and tag nothing.

**C7. Task D1 doesn't close the gap it names — and re-opens it in reverse.** (a) Only `properties.json` is added to `COPY_FILES`; the next tracked `.phronesis` file with uncommitted edits (`toolchains.json`, which Part E edits) replays the shortfall silently. Derive the dirty set from `git status --porcelain -- .phronesis/` (or diff source-vs-worktree bytes for every tracked file there), not from a list. (b) The MCP tool defaults `seed_tracked: false`, so an autonomous swarm calling `swarm_govern_worktree` with no arguments reproduces the stale-stub failure; warnings only help someone who reads them. Make the driver opt in automatically when the report warns, or default true for the MCP path. (c) `--skip-worktree` means a loader-verifier's later corroborating writes to `properties.json` in a worker are invisible to `git status` and will never merge back — the divergence is preserved in the opposite direction. State which side owns properties.

**C8. Task E2 drops negative evidence.** An unbound harness that FAILS is dropped from facts: a failing proof run yields no `proof_fail` tag, only a stderr note — a new silence, in the PR that adds a provenance tag so "the record says which evidence it rests on." Also `load_properties(...).unwrap_or_default()` converts a corrupt `properties.json` into "every harness unbound," silently discarding all proof results. **Fix:** journal unbound harnesses under a synthetic tag (e.g., `outcome:proof_unbound:<harness>`, status-preserving), and on store-load failure carry the raw harness name through and warn, or refuse the run.
